# Benchmark Protocol

This protocol standardizes markdown-focused evaluation runs for consistent comparison.

## 1. Environment

- Python 3.11+
- Dependency management via `uv` and repository lockfile
- For local backends, report hardware details (GPU model and VRAM)

## 2. Evaluation Procedure

### Dataset and Split

- Use the same dataset ID/path and split across compared runs.
- Record whether evaluation used full data or `--max-samples`.

### Reproducibility

- Set `--seed` when reproducibility is required.
- Keep model config YAML under version control.
- Preserve `protocol.json` generated by each run.

### Recommended Command

```bash
uv run main.py evaluate \
  --model-config configs/models/<model>.yaml \
  --dataset <dataset-id> \
  --split train \
  --report-format all
```

## 3. Metrics to Report

Primary metric (current flow):

- `avg_markdown_overall_score`

Supporting metrics:

- `avg_markdown_text_score`
- `avg_markdown_table_teds`
- `avg_markdown_formula_score`
- `avg_markdown_order_score`
- `empty_rate`
- `parse_fail_rate`
- `avg_latency_ms`

## 4. Prompting Guidelines

- Prefer setting prompts in `configs/models/*.yaml` under `prompts.markdown`.
- Keep prompt changes explicit in version control when comparing runs.

## 5. Versioning

- Protocol version is stored in `protocol.json`.
- Re-run benchmarks when metric definitions or pipeline behavior changes.
